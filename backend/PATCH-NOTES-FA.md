# Karvo — Accounts, Catalog و Listings V1

این نسخه شامل نه بخش است:

1. تثبیت زیرساخت تست و رفع account-enumeration در `login/request-otp`.
2. اضافه‌شدن Catalog V1 با ساختار `Brand -> VehicleModel -> VehicleTrim`.
3. هم‌راستاسازی پایه حساب کاربری با فرانت: ۹ نقش، پروفایل، دعوت و گردش‌کار تغییر نقش.
4. مقاوم‌سازی OTP در برابر قطعی Redis، broker و Celery worker با fallback امن PostgreSQL و ارسال مستقیم.
5. افزودن API واقعی ثبت آگهی، تصاویر فشرده و پروفایل‌های کامل‌تر کاربری/کسب‌وکار.
6. اتصال فهرست، جزئیات و داشبوردها به آگهی واقعی و افزودن لوگو/کاور فشرده کسب‌وکار.
7. تکمیل ویرایش آگهی، مدیریت تصاویر و ارتقای مدیریت آگهی‌ها در Django Admin.
8. افزودن علاقه‌مندی واقعی و اتصال خانه، فروش فوری، فروش ویژه و داشبورد خریدار به آگهی‌های واقعی.
9. اتصال مقایسه خودرو به آگهی واقعی و بهینه‌سازی فهرست‌های عمومی برای مقیاس بالا.

## مقایسه واقعی و کارایی

- حذف کامل داده نمونه از صفحه مقایسه و تب مقایسه داشبورد خریدار.
- افزودن انتخاب خودرو از کارت آگهی، صفحه جزئیات و هدر موبایل/دسکتاپ.
- نگهداری حداکثر چهار شناسه مقایسه در مرورگر و حذف خودکار آگهی غیرفعال.
- افزودن API گروهی مقایسه با سقف چهار آگهی و Query ثابت.
- افزودن جست‌وجوی انتخاب خودرو با debounce، لغو درخواست قبلی و Cursor Pagination.
- افزودن خروجی `summary=true` برای فهرست‌های عمومی با یک تصویر کاور و payload محدود.
- افزودن ایندکس‌های Partial و Trigram برای فید، مرتب‌سازی و جست‌وجوی سریع PostgreSQL.
- ساخت ایندکس‌های PostgreSQL به‌صورت concurrent برای جلوگیری از قفل طولانی جدول.
- افزودن تست‌های API برای سقف مقایسه، وضعیت آگهی، صفحه‌بندی و تعداد Queryها.
- افزودن تست واحد فرانت برای انتخاب، حذف، سقف چهار خودرو و پاک‌سازی آگهی غیرفعال.

## تغییرات حساب کاربری

- رفع خطای نام طولانی index مدل `VehicleModel` و افزودن migration تغییر نام.
- تعریف ۹ نقش نهایی سامانه و محدودکردن ثبت‌نام عمومی به خریدار، فروشنده شخصی و نمایشگاه‌دار.
- افزودن کد دعوت یکتا، معرف، درآمد دعوت و اعتبار قابل استفاده به کاربر.
- ثبت پاداش دعوت در زمان ثبت‌نام و دریافت یک‌باره و تراکنشی پاداش.
- افزودن مشاهده و ویرایش امن پروفایل؛ نقش از endpoint پروفایل قابل تغییر نیست.
- افزودن درخواست تغییر نقش، محدودیت یک درخواست pending و تأیید/رد فقط توسط مدیر.
- افزودن CORS برای اتصال فرانت توسعه روی `localhost:3000`.
- افزودن تست‌های API و امنیتی برای قابلیت‌های جدید.
- افزودن مدل `OtpChallenge`؛ کد OTP فقط به‌صورت HMAC ذخیره می‌شود.
- استفاده از Redis/Celery در حالت عادی و فعال‌شدن خودکار PostgreSQL/direct-send هنگام قطعی.
- افزودن تست قطعی هم‌زمان Redis و Celery و تست یک‌بارمصرف‌بودن fallback.
- افزودن استان، شهر، آدرس و روش تماس ترجیحی به پروفایل کاربر.
- افزودن نام، تلفن ثابت و معرفی کسب‌وکار برای نمایشگاه و نمایندگی.
- افزودن لوگو و کاور کسب‌وکار با فشرده‌سازی WebP قطعی در سرور.

مسیرهای حساب کاربری در `README.md` مستند شده‌اند.

## APIهای جدید

- `GET/POST /api/v1/catalog/brands/`
- `GET/PATCH/PUT/DELETE /api/v1/catalog/brands/<slug>/`
- `GET/POST /api/v1/catalog/models/`
- `GET/PATCH/PUT/DELETE /api/v1/catalog/models/<slug>/`
- `GET/POST /api/v1/catalog/trims/`
- `GET/PATCH/PUT/DELETE /api/v1/catalog/trims/<slug>/`
- `GET/POST /api/v1/catalog/listings/`
- `GET/PATCH/PUT/DELETE /api/v1/catalog/listings/<id>/`
- `POST /api/v1/catalog/listings/<id>/approve/`
- `POST /api/v1/catalog/listings/<id>/reject/`
- `GET/POST /api/v1/catalog/favorites/`
- `DELETE /api/v1/catalog/favorites/<listing_id>/`

فیلترهای V1:

- `GET /api/v1/catalog/models/?brand=bmw`
- `GET /api/v1/catalog/trims/?model=bmw-x4`
- `GET /api/v1/catalog/brands/?q=مرسدس`
- `GET /api/v1/catalog/models/?q=x4`
- `GET /api/v1/catalog/trims/?q=xdrive`

خواندن Catalog عمومی است. ایجاد، ویرایش و حذف فقط برای `is_staff=True` مجاز است.
رکورد غیرفعال برای کاربران عمومی نمایش داده نمی‌شود. حذف والد دارای فرزند با `PROTECT`
متوقف می‌شود و برای حذف منطقی باید `is_active=false` شود.

آگهی جدید فقط توسط فروشنده، نمایشگاه یا نمایندگی ثبت می‌شود و ابتدا در وضعیت `pending`
قرار می‌گیرد. کاربران عمومی فقط آگهی‌های فعال را می‌بینند؛ مالک علاوه بر آگهی‌های فعال،
آگهی‌های در انتظار خودش را نیز می‌بیند. `mine=true` برای داشبورد مالک و فیلترهای جست‌وجو،
قیمت، کارکرد، سال، وضعیت و ترتیب برای صفحه خرید اضافه شده‌اند. هر آگهی باید ۵ تا ۱۰ تصویر
معتبر JPEG/PNG/WebP داشته باشد؛ تصویر پس از اعتبارسنجی در سرور به WebP حداکثر یک مگابایت
تبدیل می‌شود.

ویرایش آگهی از همان endpoint جزئیات با `PATCH` انجام می‌شود. شناسه تصاویر نگه‌داشته‌شده با
`retained_image_ids` ارسال می‌شود و مجموع تصاویر قبلی و جدید همچنان باید بین ۵ تا ۱۰ باشد.
تصاویر جدید دوباره در سرور اعتبارسنجی و فشرده می‌شوند. ویرایش توسط مالک، وضعیت آگهی را به
`pending` برمی‌گرداند تا محتوای اصلاح‌شده قبل از انتشار دوباره بررسی شود.

در Django Admin، شناسه/برند/مدل به صفحه ویرایش لینک شده‌اند، وضعیت از جدول قابل تغییر است
و عملیات گروهی تأیید، انتقال به صف بررسی و ثبت فروش اضافه شده‌اند. آپلود تصویر از پنل ادمین
نیز از همان فشرده‌سازی WebP استفاده می‌کند.

علاقه‌مندی‌ها به حساب کاربری متصل‌اند و با خروج از حساب از حافظه فرانت پاک می‌شوند. فقط
آگهی فعال قابل ذخیره است، ثبت تکراری رکورد جدید نمی‌سازد و هر کاربر فقط علاقه‌مندی‌های خودش
را مشاهده یا حذف می‌کند. صفحه خانه، فروش فوری و فروش ویژه نیز دیگر خودروهای نمونه را به
صفحه جزئیات نمی‌فرستند و مستقیماً از Listings API داده می‌گیرند.

## تست‌ها

برای Catalog تست‌های Unit، Component، API، Security، Integration، Migration، E2E،
Regression، Smoke و Load اضافه شده‌اند.

محیط تست با Compose project مستقل `karvo-test` اجرا می‌شود و با دیتابیس/Redis محیط
Development تداخل ندارد. Load/Stress/Spike روی پورت میزبان `8001` اجرا می‌شوند، بنابراین
backend توسعه می‌تواند روی `8000` روشن بماند.

## اجرای مرحله

بعد از Extract/Copy فایل‌های Patch در ریشه پروژه:

```powershell
docker compose -f compose.yaml -f compose.dev.yaml exec backend python manage.py makemigrations --check
```

باید پیام `No changes detected` بگیرید. سپس:

```powershell
docker compose -f compose.yaml -f compose.dev.yaml exec backend python manage.py migrate
```

بعد تست سریع:

```powershell
.\run-tests.ps1 fast
```

و در صورت سبز بودن:

```powershell
.\run-tests.ps1 all
```

در پایان نیز:

```powershell
docker compose -f compose.yaml -f compose.dev.yaml exec backend python manage.py check
```

پس از اجرای migration و سبزشدن تست‌ها، فهرست خرید، جزئیات، آگهی‌های فروشنده/نمایشگاه و
صف تأیید مدیر از Listings API واقعی استفاده می‌کنند.
